# Concitech AdSense 内容质量第二轮整改设计

日期：2026-08-31

## 审核结论

AdSense 已确认站点所有权，`ads.txt` 状态为 Authorized，但在 2026-08-29 以 `Low value content` 拒绝。问题不在广告代码，而在审核系统尚未从站点中看到足够规模、原创性和可独立消费的内容。

## 方案比较

1. 再次扩写首页和项目介绍：改动小，但页面仍以导航和自我介绍为主，不能明显提升内容密度。
2. 直接把博客文章复制到主域：页面数量增加快，但会制造重复内容和 canonical 冲突。
3. 新增基于真实仓库、故障和验证记录的原创案例，同时隔离博客中的空页和极短文章：能增加主域独立价值，又保留历史 URL。本轮采用此方案。

## 主域内容

主域新增五篇实践文章：跨仓库 GitHub Actions 部署、旧版 Hexo 静态输出、X 媒体解析、浏览器截图的 CSP 边界、旧内容索引治理。每篇文章都必须说明问题、实际实现、验证方法和限制，引用本站真实代码行为，不写泛化教程。

首页只展示最新三篇，`/notes` 展示全部八篇。所有新文章输出唯一 title、description、canonical、一个 H1、作者与日期，以及与可见内容一致的 `Article` JSON-LD。sitemap 和自动检查同步覆盖这些地址。

## 博客治理

不删除历史文章。对正文规模明显不足的十一篇旧文增加 `indexing: false`：页面继续允许访问和被站内链接发现，但输出 `noindex, follow`，并从 sitemap 排除。这样避免空模板和短记录参与质量评估，同时不会制造 404。

## 验证与发布

- 主站检查必须通过 15 个页面、8 篇原创文章、canonical、内部链接、sitemap、robots、ads.txt 和广告边界。
- 博客构建后确认十一篇目标文章含 `noindex, follow`，且 sitemap 不包含这些 URL；其余文章仍可索引。
- 分别部署两个仓库并核对线上响应。
- 上线后先等待抓取信号更新，不在本次代码发布中自动勾选 AdSense 修复确认或请求复审。
